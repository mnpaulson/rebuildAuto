## 2. Build & Deployment Workflow

### Deployment Scripts:
- **`deploy.bat`**: Full deployment tool at the workspace root:
  ```bat
  .\deploy.bat           :: Compiles Release build, checks for running game client, copies DLL
  .\deploy.bat /copy     :: Fast deploy without rebuilding
  .\deploy.bat /config   :: Force-synchronizes bot_config.json from workspace to game directory
  .\deploy.bat /run      :: Builds, deploys, and automatically starts RebuildClient.exe
  ```
- **`updateclient.bat`**: The client update batch script also copies `RebuildBotPlugin.dll` to `C:\games\RagnarokRebuild\BepInEx\plugins\`.

### Direct CLI Method: MSBuild
The `.csproj` has an automated `PostBuildDeploy` target:
```powershell
dotnet build RebuildBotPlugin/RebuildBotPlugin.csproj -c Release -p:DeployOnBuild=true
```

### Critical Deployment Notes:
- **Windows File Lock**: While `RebuildClient.exe` is running, Windows locks `RebuildBotPlugin.dll`. You **must close the game client** before copying/deploying a new DLL, or use `deploy.bat` which will prompt and wait for client closure.
- **Git Protection**: `deploy.bat` is in `.gitignore` so machine-specific deployment paths remain untracked.

## 4. Critical Engineering Patterns & Gotchas

### A. IL2CPP Method Stripping (IMGUI)
> [!WARNING]
> Unity IL2CPP stripping removed internal layout methods from `GameAssembly.dll`.
> - **DO NOT USE `GUILayout`**: Calls to `GUILayout.BeginArea`, `GUILayout.BeginVertical`, `GUILayout.Space`, or `GUILayoutUtility` will throw `NotSupportedException: Method unstripping failed` or `MissingMethodException: ExitGUIException`.
> - **USE NATIVE `GUI.*`**: Always use immediate-mode unstripped primitives (`GUI.Box`, `GUI.Label`) with manual layout arithmetic (e.g. `LayoutCursor` struct in `BotGuiOverlay.cs`).

### B. Dual-Channel Tactile Click Detection
> [!IMPORTANT]
> In stripped IL2CPP builds, Unity's internal `GrabMouseControl`/`HasMouseControl` ICalls fail to track control IDs across frames. Consequently, standard `GUI.Button` returns `false` on MouseUp.
> - **Custom Click Implementation**: In `BotGuiOverlay.cs`, all buttons and toggles use `CustomButton()` with dual-channel detection:
>   1. `Event.current.type == EventType.MouseDown && rect.Contains(Event.current.mousePosition)` in `OnGUI`.
>   2. `Input.GetMouseButtonDown(0)` captured in `Update()` matched against `currentGuiMousePos`.
>   This guarantees 100% reliable click response on the first press.

### C. Click Passthrough Defense (Harmony)
> [!CAUTION]
> - **DO NOT patch `EventSystem.IsPointerOverGameObject`**: Inside `CameraFollower.Update()` (line 1777), if `pointerOverUi` is true without an actual uGUI element under cursor, `ExtendedStandaloneInputModule.GetPointerEventData().pointerEnter` evaluates to `null`, causing `NullReferenceException` every frame!
> - **CORRECT PATCHES** (in `Patches.cs`):
>   1. Patch `CameraFollower.ScreenCastV2(ref bool isOverUi)`: Prefix sets `isOverUi = true` when `BotGuiOverlay.IsMouseOverOverlay` is true, cleanly suppressing ground clicks, NPC clicks, and attacks.
>   2. Patch `NetworkManager.MovePlayer`: Prefix returns `false` if `BotGuiOverlay.IsMouseOverOverlay` is true to block any movement packets.

### D. Server Movement Packet Limit (`SharedConfig.MaxPathLength`)
- In `RebuildSharedData/Config/SharedConfig.cs`:
  `public const int MaxPathLength = 16;`
- **Server Rule**: If a `MovePlayer(Vector2Int dest)` packet specifies a coordinate where `(dest - playerPos).SquareDistance() > 16`, the server **silently discards the packet**.
- **Movement Helper**: Always use `BotEngine.Instance.SafeMoveTowards(currentPos, destination)`. It uses `RoWalkDataProvider.Instance.GetNextWalkableTileForClick(start, dest, out nextStep)` to clamp movement to valid, walkable steps within 10–12 tiles along the path.

### E. Heatmap Exploration & Fluid Movement
- `MapHeatmap.cs` tracks sector visits (16×16 tile sectors).
- Long-distance macro waypoints are chosen in cold sectors (30–100 tiles away) based on time-since-visit and distance scoring.
- Movement is **arrival-driven**: `player.IsMoving` / `player.IsWalking` is monitored. As soon as the player finishes walking a step, a new step is issued after a natural **0.3s pause**, completely avoiding static delays.

### F. Serialization & IL2CPP
- Use `System.Text.Json` with `IncludeFields = true` and `PropertyNameCaseInsensitive = true`.
- Avoid Unity's `JsonUtility` because it fails on complex IL2CPP type conversions.
- Embedded resources (such as `warps.json` with 1,742 warps) must have their model fields defined as `{ get; set; }` properties.

### G. Custom MonoBehaviour Injection
- Any custom MonoBehaviour running under IL2CPP (`BotEngine`, `BotGuiOverlay`) must:
  1. Inherit from `UnityEngine.MonoBehaviour`.
  2. Implement an interop constructor: `public MyClass(IntPtr ptr) : base(ptr) { }`.
  3. Be registered during plugin initialization in `Plugin.Load()`:
     ```csharp
     ClassInjector.RegisterTypeInIl2Cpp<BotEngine>();
     ClassInjector.RegisterTypeInIl2Cpp<BotGuiOverlay>();
     ```

### H. Logging Guidelines
- Avoid in-game IMGUI log boxes.
- Dispatch all logging through `Plugin.LogInfo(msg)` (via `ManualLogSource`), which prints cleanly to the BepInEx terminal window.
